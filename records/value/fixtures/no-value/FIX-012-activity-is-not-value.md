# FIX-012 — activity is not value

> **Fictional worked fixture.** Meridian Mutual is invented.

**Proves:** a programme paper full of delivery language yields no value candidate unless material
binds the activity to an organisational state change. Work is not an outcome.

## Source

**A — Programme paper, `crm-programme-update.md`**

> The CRM replacement enters build phase in September. Milestones: data model signed off (July),
> integration complete (November), pilot branch go-live (January), full deployment by end Q1.
> The programme board approved the revised plan on 12 June. Delivery confidence: amber.

Plans, milestones, an approval *of a plan*, and a delivery status. No organisational outcome is
stated anywhere — what changes for whom when the CRM exists is absent.

## Expected

- At most `context` and `time` contributions (the programme timeline, usable to interpret value
  material found elsewhere), each `epistemic_confidence` low for value purposes.
- **Zero CandidateAssemblies**, with the boundary test named: value ≠ activity — ✗ *implement CRM* /
  ✓ *customers receive consistent service regardless of channel*, and the second appears nowhere in
  this material.
- The programme-board approval flagged as a possible **decision** identification lead — routed to
  the decision language, not manufactured into value.

## Must not

- Draft a candidate whose commitment is "deliver the CRM programme".
- Treat "full deployment by end Q1" as a `due-point` for a value commitment that does not exist.
- Convert delivery confidence (amber) into value evidence of any kind.
- Suppress the decision lead because this is a value pass — cross-language leads are reported, per
  the shared identification skill.
