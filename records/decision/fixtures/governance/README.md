# Governance fixtures

**Status:** proposed under [TDR-0034](../../../../decisions/TDR-0034-governance-reconstruction-and-forum-evolution.md).
Not accepted, and carrying no standing.

Fourteen known-answer cases for the [governance skills](../../skills/governance/), exercising the
[deterministic rules](../../validation/governance-rules.md). Everything here is fictional and marked as
such, per [`CONTRIBUTING.md`](../../../../CONTRIBUTING.md) — **Kingsmere Bank plc**, Project Ashcombe
and every individual named are invented.

One estate, one spine. Project Ashcombe — replacing Kingsmere's arrears-contact decisioning with an
automated, model-driven contact strategy, approved at a Technology Design Authority on 2026-02-11 —
is the consequential decision each fixture reconstructs from a different angle. The artefacts overlap
deliberately, because a real governance estate is not a set of independent documents.

| Fixture | Category | Proves |
|---|---|---|
| [FIX-018](FIX-018-tda-real-jobs-not-stated-purpose.md) | Forum reconstruction | A forum's stated purpose is evidence of what it is *for*, and of nothing about what it *does* |
| [FIX-019](FIX-019-policy-with-no-traceable-authority.md) | Authority gap | An unlocated origin stays `UNKNOWN` — and a legitimate `UNKNOWN` carries zero references, a question and a search scope |
| [FIX-020](FIX-020-contradictory-governance.md) | Contradiction | Two accountable executives, no supersession — never resolved by recency, seniority or document type |
| [FIX-021](FIX-021-historical-boundary.md) | Historical boundary | A June audit report may not explain a February decision |
| [FIX-022](FIX-022-external-obligation-duplicated-internally.md) | Regime preservation | Evidence reuse is available; removing a mandated mechanism is not |
| [FIX-023](FIX-023-tda-and-risk-assemble-the-same-evidence.md) | Duplication | The same pack assembled twice, with different cut-off dates |
| [FIX-024](FIX-024-tda-evolution-conformance-and-trade-off.md) | Forum evolution | Precompute the deterministic conformance; keep the cross-domain trade-off human and authorised |
| [FIX-025](FIX-025-risk-forum-independent-challenge.md) | Independence | The efficiency case for consolidation is real, and refused |
| [FIX-026](FIX-026-waiver-with-expired-condition.md) | Waiver | An expired condition is never renewed by continued reliance |
| [FIX-027](FIX-027-retirement-candidate-only-after-reuse-proven.md) | Disposition | `RETIRE_CANDIDATE` is a question, and needs its proof named |
| [FIX-028](FIX-028-stale-policy-and-forum-authority-ambiguity.md) | Authority ambiguity | Two forums, one object, no precedence — and noting is not approving |
| [FIX-029](FIX-029-nothing-here.md) | Negative | Governance vocabulary everywhere, no governance finding |
| [FIX-030](FIX-030-multiplicity-is-not-independence.md) | Separated powers | Seven powers reconstructed separately; "independent oversight" that is not independent |
| [FIX-031](FIX-031-population-sensing-precondition.md) | Cadence | The control became redundant; the cohort view did not |

FIX-025 and FIX-031 are the two whose failure produces output that looks **better** than a pass — a
tidy consolidation, a leaner meeting calendar — which is why both must be run every time and neither
may be judged by how the recommendation reads.

The cross-language case lives outside every package: a complaint challenging the Ashcombe decision is
[CORPUS-006](../../../../tests/corpus/CORPUS-006-complaint-challenging-a-decision.md), because it
yields both a decision-side reconstruction and a value-side commitment.

Each case states **Expected** and **Must not**. A run satisfying only the first has not passed —
producing the right finding by the wrong route will be wrong and undetectable on real material
([TDR-0025](../../../../decisions/TDR-0025-conformance-architecture.md)).
