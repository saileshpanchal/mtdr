# Package — Work

**Language:** work · **Primary record (proposed):** `OIR` — Operational Inheritance Record
**Status:** `candidate` — the [record admission test](../../specification/record-admission-test.md)
has **not** been passed.

## Semantic scope (reserved, not admitted)

Operational work and inheritance: the job to be done, and the capabilities, knowledge, relationships,
resources and operating context a participant inherits to perform it — through human, hybrid and
AI-first transitions. JTBD is the job grammar *within* this scope; it is not a separate language and
creates no record of its own.

Bounded against the existing languages: a **decision** (TDR) may reshape what is inherited; a **value
commitment** (VR) may be what the work pursues. This language would carry neither judgement nor
purpose — only the governed context of performance. One open question belongs to admission rather
than to this README: whether operational inheritance is persistent governed state at all, or a
participant-specific projection *from* governed state. The admission test's question 4 exists for
exactly that distinction, and a directory must not settle it.

## What this package contains

This README. Nothing else — **candidate packages contain metadata and scope only**
([TDR-0021](../../decisions/TDR-0021-record-package-architecture.md)). No specification, schema,
template, examples, validation rules or skills exist until admission succeeds, and none may be added
here before it. A directory confers no maturity.
